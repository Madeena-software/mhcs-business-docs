Doctor · detailed user flow

Claim to report

01

Dispatch & queue

WhatsApp offer, temporary clinical workspace

Authentication

Receive an eligible case offer in WhatsApp

Verified professional identity, credentials, specialty, service permission, and modality eligibility are checked before the case can be opened.

Shared queue

Accept or decline the minimal-information offer

Only eligible cases are offered. The case context is expanded inside the temporary Clinical / DICOM Workspace after acceptance.

Claim

Was the case claimed successfully?

NoAnother doctor won the claim; refresh and select another case.
YesAccept the offer and open the temporary Clinical / DICOM Workspace.
History

Open `KASUS SAYA / RIWAYAT SAYA` in WhatsApp

Receive a concise professional history. Detailed inspection, when justified, opens a secure temporary Doctor History surface and returns to WhatsApp.

02

Study review

Inspect authorised material

Review

Open the assigned case workspace

View only the examination and clinical context justified by the assignment and specialty authorization.

Optional access

Is raw DICOM clinically necessary?

NoContinue in the built-in viewer.
YesUse a short-lived, authorised, audited download link.
Independent AI

View AI output when available

The doctor may use it as supporting information but never waits for it.

Release option

Release the case if review cannot continue

Return it to the shared queue before final submission.

03

Draft & submit

Finalise clinical work

Draft

Write and freely edit the report

The report remains editable until Submit.

Clinical check

Is the report complete and ready?

NoContinue reviewing and editing the draft.
YesSubmit the final report.
Submit effects

Lock report and create payment eligibility

The submitted report becomes immutable and doctor earning becomes eligible.

Publication

Return the report to Member Core

Member Core sends a WhatsApp notification and issues a secure temporary result link when required; the Doctor Workspace is temporary and is not a permanent doctor portal.

04

Correction lifecycle

Never overwrite history

Later decision

Is a clinical correction necessary?

NoThe submitted report remains current.
YesCreate a new amendment at any necessary time.
Amend

Record reason, doctor, timestamp, and signature

Identify the version being superseded and preserve the original report.

Redistribute

Record the amendment and notify through WhatsApp

The amendment becomes current while the full history remains traceable; Member Core coordinates member-safe delivery.

Payment rule

Do not create another doctor payment

A correction remains part of the original paid review.
